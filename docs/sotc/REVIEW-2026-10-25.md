# Review: launcher, updates and preparation

Baseline: `10b30c1`. This pass fixes reproducible host-side defects; it does not add shader
backports or claim to fix the untriaged `0x490a0` crash.

## Findings fixed

| Priority | Finding | Change |
|---|---|---|
| P1 | The updater could overwrite protected files through Windows case aliases or links. A failed rollback lost its remaining backups at the next launcher start. | Validate Windows archive paths on every host, reject duplicate names and links/junctions in replaced paths, and protect `user`, `update` and existing `sotc.ini` case-insensitively. Keep the recovery marker, backups and staging files after an incomplete update; block another update until recovery. |
| P1 | A clean checkout could not be packaged because `window_icon.png` is a local, untracked export. | Package the tracked `window_icon.ico`; both the launcher and package accept the optional PNG without requiring it. |
| P1 | Auditing the release ZIP found dozens of missing indirect FFmpeg/SDL DLL imports. The frozen-launcher smoke test did not start the native loader, so an installed MSYS2 could hide the broken package. | Walk the complete PE dependency graph, reject unresolved non-system DLLs, ship the CLANG64 licenses, and smoke-test `bb-probe.exe` with only Windows system directories on PATH. |
| P2 | F1 saved `upscaler=dlss`, but the launcher did not offer it. Selecting FSR 1/bilinear did not disable automatic DLSS, and selecting DLSS disabled its FSR 1 fallback. | Share `SOTC_UPSCALER` and a single live mode across the launcher, presenter, input capture and overlay. Keep NGX availability separate from selection. Preserve existing FSR 1/bilinear choices. |
| P2 | DLSS received RCAS attenuation as sharpness, reversing High/Low. Resuming DLSS after skipped frames retained stale temporal history. | Convert attenuation to decreasing sharpness and reset history on the fallback path. The parameter mapping is tested; actual image quality still requires Windows/RTX verification. |
| P2 | Preparation ignored `param.sfo` changes, retained removed update modules and could accept an old success stamp after a failed rebuild. | Fingerprint metadata and overlay provenance, select the effective source before copying, remove stale generated files, and invalidate stamps before modifying outputs. |

The updater now declares pointer-sized Windows handle types and refuses to replace files if
waiting for the launcher fails or times out. It does not restart an incompletely restored port.

## Recovery after an interrupted update

When `update/recovery-needed` exists, the launcher warns rather than claiming the old version
was restored. Neither cleanup nor another update removes the backup or staging files.

Close the game, launcher and applier before recovery. Inspect `update/update.log` and restore
the original files from `update/backup` to the corresponding paths in the port directory, or
repair the application from a known-good release while retaining saves and configuration.
Remove `update/recovery-needed` only after verifying the installation has been recovered.

## Release preparation

v0.63 remains a prerelease until Windows/RTX gameplay validation. The updater now follows
`hellomrli/ShadowOfTheColossus-PC` rather than upstream; its stable feed does not offer previews.
The Windows workflow also smoke-tests the frozen launcher's script mode, bundled updater,
Tcl/Pillow resources and shipped icon before uploading the package. A separate native-loader
smoke test excludes MSYS2 from PATH and starts in an empty directory; reaching its usage message
proves the loader's DLL imports resolve without requiring a game dump or Vulkan GPU.

## Remaining test gaps

- The full GPU/Windows build and in-game DLSS paths were not executed here. CMake, SDL3/fmt and
  initialized third-party submodules are missing; the standalone test does not validate Vulkan
  resource lifetime, synchronization, NGX evaluation or image quality.
- Existing `motion-history-test` and `ui-composition-test` cannot compile: their included
  `motion_history.h` and `ui_composition.h` are already absent at the baseline commit. The
  legacy CMake test declarations need a separate cleanup/replacement pass.
- Direct Linux C test builds with the project's `-Werror` flags also fail on existing code:
  `runtime_file.c` reports format truncation in `runtime_file_configure`; `runtime_content.c`
  has Windows-only helpers reported as unused. These are not counted as passing tests.

Before a stable release, run the checks in `DLSS.md`, especially mode changes followed by a
launcher restart, `SOTC_DLSS=0`, menu/movie fallback, and resuming DLSS. A successful Windows
build or package smoke test does not replace these in-game checks. Existing gameplay crashes
still need the player's dump/log evidence described in `CRASH-0x490a0.md`.
